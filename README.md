# Multi-Agent Market Research Application

A sequential multi-agent market research application built with **Python**, **Streamlit**, **Pydantic**, **DuckDuckGo Search (`ddgs`)**, and **Google Gemini (`google-genai`)**. Given a company or industry query, the system orchestrates four specialized agents—**Orchestrator**, **Researcher**, **Analyst**, and **Critic**—to gather live web evidence, synthesize a grounded brief, validate accuracy with at most one revision cycle, and export a clean Markdown report.

---

## Architecture & Workflow

```text
User Query (Streamlit UI)
        │
        ▼
  [Orchestrator] ── Initializes ResearchState & coordinates execution
        │
        ▼
   [Researcher]  ── Generates focused search queries & gathers deduplicated web findings via ddgs
        │           (falls back gracefully to sample_fallback if offline/empty)
        ▼
    [Analyst]    ── Synthesizes findings into a structured Pydantic ResearchBrief
        │           (Topic Summary, Up to 2 Competitors, Key Observations, Sources, Missing Information)
        ▼
     [Critic]    ── Audits grounding, completeness, and structure against gathered findings
        │
        ├── Approved ──────────────────────────────► Final Brief + Markdown Export
        └── Revision Needed (max 1 loop) ──► [Analyst Revision] ──► [Final Critic Review] ──► Final Brief
```
---

### Design Choices
* **Shared Typed State (`schemas.py`):** All agents read from and update a single `ResearchState` Pydantic model (`SearchFinding`, `CompetitorInfo`, `ResearchBrief`, `CriticReview`), eliminating brittle string parsing between stages.
* **Grounded Synthesis:** The Analyst is instructed not to fabricate market share percentages, revenue numbers, or statistics absent from the retrieved snippets, explicitly documenting data gaps under **Missing Information**.
* **Bounded Revision Loop:** The Orchestrator allows at most **1 revision** (`revision_count < 1`) when the Critic flags concrete gaps, guaranteeing predictable latency and cost.
* **Clean Source Handling (`tools.py`):** DuckDuckGo search results are deduplicated across sub-queries, ad-redirect URLs are unwrapped to clean destination links, and an offline fallback record prevents crashes if search results are unavailable.

## Project Structure

    market-research-agent/
    ├── app.py              # Streamlit UI, live workflow status, brief rendering, and .md export
    ├── agents.py           # Orchestrator, Researcher, Analyst, and Critic workflow logic
    ├── schemas.py          # Pydantic models for state, findings, brief, and critic review
    ├── llm.py              # Gemini structured-output client wrapper
    ├── tools.py            # DuckDuckGo web search tool with URL cleanup and error handling
    ├── requirements.txt    # Project dependencies
    ├── .env.example        # Environment variable template
    ├── .gitignore          # Git ignore rules
    ├── sample_output.md    # Sample exported brief generated by the app
    └── README.md           # Project documentation

## Local Setup & Running the App

### 1. Clone the Repository
    git clone https://github.com/ritikdes/market-research-agent.git
    cd market-research-agent

### 2. Create & Activate a Virtual Environment
**Windows (PowerShell):**
```powershell
    python -m venv venv
    .\venv\Scripts\Activate.ps1
 ```   

**macOS / Linux:**
```powershell
    python3 -m venv venv
    source venv/bin/activate
```

### 3. Install Dependencies
    pip install -r requirements.txt

### 4. Configure Environment Variables
Copy `.env.example` to `.env` and add your Gemini API key:
    cp .env.example .env

Edit `.env`:
    GEMINI_API_KEY=your_actual_gemini_api_key

### 5. Launch the Streamlit Application
    streamlit run app.py

Open `http://localhost:8501` in your browser, enter a company or industry query (e.g., `Analyze the electric vehicle (EV) market in Nepal.`), click **Run Research**, and download the generated brief as Markdown.
